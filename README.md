## Core Competencies & Knowledge Domains

* **Incident Scoping & Triage:** Identifying problem scope (single user vs. multi-user/network-wide impact), establishing symptoms, and formulating step-by-step diagnostic workflows.
* **Customer Interaction Framework:** Implementing the "Know, Relate, and Understand" communication model; managing difficult or talkative end-users via active listening, polite refocusing, and direct questioning without technical jargon.
* **Remote Support Administration:** Pre-session communication, software compatibility verification (e.g., VNC, RDP), secure end-user authorization, and hands-on remote troubleshooting.
* **AI-Assisted Ticketing Systems:** Utilizing AI agents for automated routine task handling, data-driven ticket classification, and predictive performance analysis while retaining human verification of technical solutions.
* **Documentation & Knowledge Management:** Formulating reproducible incident records, updating structured knowledge bases, and compiling Standard Operating Procedures (SOPs).

## Help Desk Standard Operating Procedure (SOP)

### SOP-001: First-Contact Incident Resolution & Remote Support

#### 1. Identification & Problem Definition
1. Gather detailed symptoms from the user without interruption during the first 60 seconds of problem description.
2. Politely refocus the dialogue using targeted, direct questions to establish:
   - What changed immediately prior to the failure (e.g., recent software installations, driver updates, network changes)?
   - The scope of the failure: Is this localized to one machine/application, or affecting multiple users?
3. Record initial ticket metadata: user ID, machine hostname, IP address, severity level, and specific error codes.

#### 2. Theory Formulation & Testing
1. Formulate a probable cause based on verified symptoms and knowledge base records.
2. Test the most accessible/least disruptive theory first (e.g., verify email server IMAP/SMTP configurations, roll back a conflicting recent application).
3. If the initial theory fails, re-evaluate symptoms to identify overlooked variables before escalating.

#### 3. Remote Assistance Protocol
1. **Consent & Verification:** Communicate expected actions, session length, and potential reboots to the user before launching the connection.
2. **Access Execution:** Verify compatibility across both host and client endpoints (e.g., cross-platform VNC/RDP tools).
3. **Execution & Privacy:** Confirm sensitive user files are closed; maintain verbal or chat communication throughout the active session.

#### 4. Resolution & Documentation
1. Verify complete functionality with the user present.
2. Log all diagnostic steps, tests, and resolution specifics in the ticketing system.
3. If the solution resolves a novel or recurring issue, submit a draft entry to the internal Knowledge Base repository.

## Course Notes & Module Artifacts

### Cisco NetAcad 1.2.3: Customer Types & Ticketing Systems

#### Communication Strategies
* **Frustrated / Angry Users:** Practice active listening, keep a calm tone, don't interrupt, and set clear expectations.
* **Non-Technical Users:** Use plain English, avoid technical jargon/acronyms, and guide them step-by-step.
* **Tech-Savvy Users:** Respect their input and details, but logically verify basic steps.
* **Talkative Users:** Politely acknowledge their comments, then gently steer the conversation back to troubleshooting.

#### IT Ticketing System Workflow
1. **Intake / Logging:** Capture the user's name, contact info, and clear problem symptoms.
2. **Categorization:** Tag the issue appropriately (*Hardware*, *Network*, *Access/Identity*).
3. **Prioritization:** Determine impact vs. urgency (Low, Medium, High, Critical).
4. **Work Notes:** Keep precise, detailed troubleshooting logs for team visibility.
5. **Resolution:** Verify the fix with the user before closing out the ticket.
